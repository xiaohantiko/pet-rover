# 控制板台架程序

这不是可放在地面上运行的整车控制器。网页模拟器不连接串口。四个程序每次只烧录一个，重刷后上一个程序不再运行。所有实验先移开宠物、拔掉充电线；软件超时不是硬件急停。

| PlatformIO 环境 | 作用 | 旋转风险 |
|---|---|---|
| `bench_monitor`（默认） | 真实串口、开关和编码器读数；可演练点动状态机 | 代码输出占空比始终为零，初测仍不要接电机电源 |
| `range_probe` | 从 7 路复用测距器输出读数及无效标志 | 所有驱动信号保持低，断开电机供电 |
| `ble_probe` | 手机 BLE 验证：按住就地按钮广播 PetRover-Bench，在通用 BLE 调试客户端连接，读自定义服务 `07040121-fd38-4c1b-a4b9-7e016c104008` 下的只读特征，预期 `bench-v1;motion=disabled`；只演示发现和读取，不传视频、Wi-Fi 密码或接收运动指令 | 所有驱动信号保持低，断开电机供电 |
| `raised_wheel_jog` | 本地按住使能、闭合保护回路后，一次只允许一个轮子、一次短脉冲 | **仅车轮悬空、固定机身、有人在硬件急停旁才可使用** |

## 编译与连接

测试基线：PlatformIO Core 6.1.18、Espressif32 平台 6.10.0（Arduino-ESP32 2.0.17）和 ESP32-S3 DevKitC-1。有 USB 转串口的板插 UART 口，用能传数据的线。在此目录执行：

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install platformio==6.1.18
pio run -e bench_monitor -e range_probe -e raised_wheel_jog -e ble_probe
pio device list
```

确认所选端口只连接本样机、已拔掉电机供电后，用 `pio run -e bench_monitor -t upload --upload-port <实际端口>` 烧录默认只读版。串口终端设置 115200 8N1、每行末尾 LF（或 CRLF）；`STATUS` 回车可读取程序模式、保护回路/使能状态、逻辑输出、两轮编码器累计值。若使用 `pio device monitor -p <实际端口> -b 115200`，建议启用 send_on_enter 过滤器或用图形串口终端发送整行。测距程序另用 `range_probe` 替换环境名后烧录；保存输出文本供离线分析，无有效距离不等于无障碍。

## 串口协议（仅台架）

- `STATUS`：只读，不延长点动。编码计数为 A 上升沿、B 判向，非四倍频；手转轮一圈记录带符号增量，符号取决于接线方向。
- `STOP`：解除逻辑输出；若要重新进入点动，先松开再按住就地使能。断线/超时不会自动恢复。
- 先松开再按住就地按钮，保护回路闭合；发 `ARM`，1 秒内再发 `L+` / `L-` / `R+` / `R-`。建议双行宏发送 `ARM\nL+\n`，不要自动循环，也不要绕过物理开关。
- 只有显式选择架空版才产生 PWM：单轮上限 36/255、最多 140 ms **软件请求时长**，不保证断电时刻或实际刹停距离。上电时一直按住按钮不能解锁。重复点动、错误命令、松手或断开互锁均终止本次；需再次人工松按。若电机未转，不要增加占空比或拼接成长脉冲。
- 仅靠串口与软件不能应对 MCU 卡死或驱动板手动测试按钮；驱动必须另有断开牵引电源的硬件路径。程序不读取充电状态、阶梯和前方障碍后做闭环控制，不可接网页或 Nav2 直接驱动车辆。

## 在电脑上复测逻辑（不需要板）

```sh
c++ -std=c++11 -Wall -Wextra -Werror -Iinclude tests/jog_guard_test.cpp -o /tmp/pet-jog-guard && /tmp/pet-jog-guard
```

上板前后应分别验证：开关断线拒绝点动，串口不再发送时脉冲自行结束，主机重连不会重放，急停物理切除电机电压。不要用软件测试结果替代这些步骤。
