# 手机短语音对讲与回听（独立台架）

在电脑即可试；与运动控制、AI、充电互相独立，不产生任何轮子指令。实现的是**半双工语音留言**，不是连续直播或实时电话。按住采手机声音、松手发出；反向按一次取车端两秒录音，手动播放。测试默认不碰任何真实音频设备。

## 1. 不用麦克风的第一次运行

从公开仓库根目录：

```sh
python3 audio/intercom.py
```

在本机打开 `http://127.0.0.1:8767`，将终端刚显示的一次性口令填入（不进 URL、不保存浏览器密码、不发截图），点“连接并查看设备模式”。应显示“合成测试音 / 模拟接收”。点“发送测试音”应显示接收 0.35 秒，电脑和车都不会响。点“取车端 2 秒音频”，再点网页播放器，可用电脑扬声器**自愿回听**合成音。不要勾选手机麦克风也能完成这两项。关页面清除临时音频，Ctrl-C 停服务；重新启动默认换口令。若要自己管理口令，可通过 `PET_AUDIO_TOKEN` **环境变量或私有密钥管理工具**提供至少24个随机的可打印 ASCII 非空格字符；设环境变量时终端不再打印具体口令。

## 2. 接上树莓派的真实声音设备

确保现场人员知情同意、远离宠物耳部，先把**物理音量**调低；数字增益限制不能保证听觉安全。Pi 上需要能录放的 USB Audio Class 设备、Linux ALSA 的 `arecord` 和 `aplay`（`alsa-utils`）。这些是扩展依赖，模拟模式只需要 Python 标准库。

```sh
arecord -L
aplay -L
```

分别从两个列表挑能支持单声道 16kHz 的设备名；若硬件不原生支持，用列表里对应的 `plughw` 名称。只允许播放的示例（将名字替换成实际输出）：

```sh
python3 audio/intercom.py --allow-live-audio --play-device 'plughw:CARD=Device,DEV=0'
```

此时车端 microphone 仍是合成音。若明确需要录真实声音，再加 `--record-device 'plughw:CARD=Device,DEV=0'`；也可只选输入不选输出。选了实设备却没有 `--allow-live-audio` 时不会启动。没有 ALSA 不会假装已录放；设备忙、超时或采样率错误返回 503，退回合成模式排查。一次输入固定2秒；机端不会持续采集、存文件或保留历史。一个抢到口令的人可以反复点录音，因此只在有人监护的安静私网会话开启，用完结束服务/断开麦克风。

## 3. 手机上按住说话

手机使用麦克风需要浏览器的**受信任 HTTPS 安全上下文**及单独授予站点麦克风权限。普通 `http://树莓派局域网IP` 不可代替。推荐在自家网内为局域网主机准备带匹配域名、手机信任的服务器证书/私钥；不要安装不明证书或将服务映射到公网。暂无证书的用户先在同一电脑用 localhost 完成上面的演示，不必为试音暴露服务。

```sh
python3 audio/intercom.py --bind 0.0.0.0 --port 8767 \
  --cert /private/example/cert.pem --key /private/example/key.pem
```

`/private/example/...` 仅为用户自备路径示例。手机访问证书域名而非 `0.0.0.0`，输入本次口令。服务没有显式允许真实扬声器时仍然只模拟接收。勾选“允许本次使用手机麦克风”，按住键；第一次按住可能要先授权，松手后再按。看到“录音中”后说话，松开发送，4 秒到顶自动结束并发送；切回后台或取消触摸则丢弃未发语音。口令仅适用于此独立服务，不与公开模拟器/摄像头混用。服务端对收听和播报共用一把锁，设备忙返回 409 而不是把旧指令排队。

## 4. 复测

```sh
python3 -m unittest discover -s audio -p 'test_*.py' -v
```

此命令在本机临时 HTTP 服务上验证合成音往返、鉴权、忙状态、输入界限。实际手机权限、树莓派 ALSA 驱动、声压、延迟和回声必须在装机后由现场人员验证；电脑测试不能证明真实设备正常。
